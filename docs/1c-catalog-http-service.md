# ТЗ для 1С-разработчика: выгрузка каталога для AI-консультанта BDB

## Задача

AI-консультант BDB в Telegram отвечает клиентам по нашему каталогу: подбирает модель по техническим параметрам, называет цену и наличие. Данные берутся из 1С. Нужно сделать в 1С **HTTP-сервис**, который отдаёт весь каталог одним JSON, и (по желанию) **регламентное задание**, которое отправляет тот же JSON на наш сайт.

Сайт поддерживает два режима, они переключаются в админке сайта:

| Режим | Кто инициирует | Что делает 1С |
|---|---|---|
| **Pull** (основной) | Сайт, раз в час | Отвечает на `GET` по HTTPS с Basic-авторизацией |
| **Push** | 1С, раз в час | Отправляет `POST https://<сайт>/api/catalog` с заголовком `Authorization: Bearer <токен>` |

JSON в обоих режимах **одинаковый**. Достаточно сделать одну функцию «сформировать каталог» и вызывать её и из HTTP-сервиса, и из регламентного задания.

---

## 1. HTTP-сервис (режим Pull)

- Метод: `GET`, адрес, например, `https://1c.bdb.uz/<база>/hs/bdb/catalog`.
- Только **HTTPS** (публикация через Apache/IIS с сертификатом). По HTTP сайт подключаться не будет.
- Авторизация: **Basic**. Отдельный пользователь 1С (например, `bdb_site`), у которого есть только роль на чтение этого сервиса: без интерактивного входа и без прав на запись.
- Если можно, разрешите доступ только с IP нашего сервера (его сообщим).
- Ответ: `200`, `Content-Type: application/json; charset=utf-8`, тело описано в разделе 3.
- Если при формировании произошла ошибка, верните `500` с телом `{"error": "текст"}`. **Никогда не отдавайте неполный список с кодом 200**: товары, которых нет в выгрузке, сайт скрывает от AI.
- Время ответа не больше 30 секунд для 5 000 товаров. Данные собирайте одним-двумя запросами (`Запрос`), а не обходом объектов.

## 2. Регламентное задание (режим Push, опционально)

- Раз в час собирает тот же JSON и отправляет его через `HTTPСоединение` (HTTPS) методом `POST` на `https://<сайт>/api/catalog`.
- Заголовки: `Authorization: Bearer <токен>` (токен выдаётся в админке сайта и хранится в 1С в защищённом виде) и `Content-Type: application/json`.
- Ответ сайта:
  ```json
  { "accepted": 1480, "rejected": [{ "sku": "X1", "error": "prices.end_user must be an integer" }], "hidden": 3 }
  ```
  Если `rejected` не пустой, запишите его в журнал регистрации.

  | Код | Значение | Что делать 1С |
  |---|---|---|
  | `200` | Выгрузка принята (`status: "ok"`) | Записать `rejected` в журнал, если он не пустой |
  | `401` | Неверный или отсутствующий токен | Не повторять; проверить токен в настройках |
  | `409` | На сайте включён режим Pull, или идёт другая загрузка (текст в `error`) | Во втором случае повторить через минуту |
  | `413` | Тело больше 20 МБ | Не повторять; сообщить нам |
  | `422` | Выгрузка отклонена целиком (`status: "refused"` / `"failed"`, причина в `error`, см. раздел 5) | Исправить и отправить заново |
  | `429` | Слишком много запросов или неверных токенов | Повторить через 10 минут |

## 3. Формат JSON

Кодировка UTF-8, даты в ISO 8601 с часовым поясом Ташкента (`+05:00`).

```json
{
  "generated_at": "2026-11-24T10:00:00+05:00",
  "currency": "UZS",
  "products": [
    {
      "sku": "ZD421T-203",
      "brand": "Zebra",
      "model": "ZD421t",
      "category": "label_printer",
      "name": { "uz": "Zebra ZD421t etiketka printeri", "ru": "Принтер этикеток Zebra ZD421t" },
      "prices": { "end_user": 6500000, "dealer": 6100000, "partner": 5800000 },
      "stock": { "status": "in_stock", "qty": 12 },
      "lead_time_days": null,
      "warranty_months": 12,
      "params": {
        "print_method": "thermal_transfer",
        "print_width_mm": 104,
        "resolution_dpi": 203,
        "connectivity": ["usb", "lan"]
      },
      "use_cases": ["retail", "warehouse"],
      "accessories": ["RIB-WAX-110x300"],
      "active": true
    }
  ],
  "clients": [
    {
      "price_group": "dealer",
      "company": "Oila Market",
      "inn": "301234567",
      "phones": ["+998901234567", "+998712345678"]
    }
  ]
}
```

### Поля товара

| Поле | Тип | Обязательно | Откуда в 1С / правила |
|---|---|---|---|
| `sku` | строка ≤ 64 | да | Артикул или код номенклатуры. **Не должен меняться**: это ключ товара на сайте. Уникален в выгрузке. |
| `brand` | строка ≤ 64 | да | Производитель / марка |
| `model` | строка ≤ 100 | да | Модель без бренда |
| `category` | строка | да | Одно значение из списка в разделе 4 |
| `name` | объект `uz` / `ru` / `en` | хотя бы один язык | Наименование для клиента. Если есть только русское, достаточно `ru`. |
| `prices.end_user` | целое ≥ 0 | да | Цена конечного покупателя, сум **с НДС**, без копеек |
| `prices.dealer` | целое ≥ 0 или `null` | нет | Цена для дилеров, сум с НДС |
| `prices.partner` | целое ≥ 0 или `null` | нет | Цена для партнёров, сум с НДС |
| `stock.status` | строка | да | `in_stock` (есть) · `low` (мало) · `to_order` (под заказ) · `out` (нет) |
| `stock.qty` | целое или `null` | нет | Свободный остаток по всем складам продажи (без резервов). Отрицательный остаток считается как 0. |
| `lead_time_days` | целое или `null` | нет | Срок поставки в днях для `to_order` |
| `warranty_months` | целое или `null` | нет | Гарантия |
| `params` | объект | нет | Технические параметры: ключи из раздела 4, значения числом или строкой без единиц. Единица измерения указана в имени ключа. |
| `use_cases` | массив строк | нет | `retail`, `warehouse`, `production`, `pharmacy`, `textile`, `horeca`, `logistics`, `medical`; другие значения игнорируются |
| `accessories` | массив `sku` | нет | Подходящие расходники и аксессуары (риббон к принтеру, этикетка к весам) |
| `active` | логическое | да | `false` = скрыть от AI (снят с продажи), но не удалять |

### Клиенты с особыми ценами (`clients`)

Сюда попадают **только партнёры и дилеры**. Конечных покупателей не передавайте: все, кого нет в списке, получают цену `end_user`.

| Поле | Правила |
|---|---|
| `price_group` | `partner` или `dealer` (вид цен контрагента / соглашения) |
| `company` | Наименование контрагента |
| `inn` | ИНН, только цифры |
| `phones` | Все телефоны контактных лиц в формате `+998XXXXXXXXX` |

Как сайт использует этот список: клиент в Telegram получает цены своей группы только если поделился номером кнопкой «Поделиться контактом» (номер подтверждён Telegram) и этот номер есть в `phones`. Партнёр видит все три цены, дилер видит `dealer` и `end_user`, все остальные видят только `end_user`. Поэтому номера должны быть актуальными.

## 4. Категории и ключи `params`

Отправляйте только ключи, которые заполнены в 1С. Можно добавлять свои ключи: сайт их примет и покажет AI как есть. Но для перечисленных ниже характеристик используйте именно эти имена: по ним AI сравнивает модели.

| `category` | Ключи `params` (допустимые значения) |
|---|---|
| `label_printer` | `print_method` (`thermal_direct` / `thermal_transfer`), `print_width_mm`, `resolution_dpi`, `print_speed_mm_s`, `connectivity` (массив: `usb`, `lan`, `wifi`, `bluetooth`, `serial`), `class` (`desktop` / `industrial` / `mobile`), `max_media_width_mm`, `media_core_mm`, `max_ribbon_length_m`, `ribbon_core_mm`, `ribbon_ink_side` (`in` / `out` / `both`) |
| `receipt_printer` | `paper_width_mm` (58 / 80), `print_speed_mm_s`, `connectivity`, `auto_cutter` (true/false) |
| `scanner` | `code_types` (`1d` / `2d`), `form` (`handheld` / `presentation` / `fixed`), `wireless` (true/false), `connectivity`, `reads_screens` (true/false), `reads_datamatrix` (true/false), `ip_rating` (например, `IP52`) |
| `tsd` | `os`, `screen_inch`, `scanner_type` (`1d` / `2d`), `ram_gb`, `storage_gb`, `battery_mah`, `ip_rating`, `freezer` (true/false), `cellular` (true/false), `nfc` (true/false), `rfid` (true/false) |
| `label` | `material` (`thermal_paper` / `tt_paper` / `synthetic` / `nylon` / `satin` / `other`), `width_mm`, `height_mm`, `labels_per_roll`, `core_mm`, `outer_diameter_mm`, `winding` (`in` / `out`), `freezer` (true/false) |
| `ribbon` | `type` (`wax` / `wax_resin` / `resin`), `width_mm`, `length_m`, `core_mm`, `ink_side` (`in` / `out`) |
| `receipt_paper` | `width_mm`, `length_m`, `core_mm`, `outer_diameter_mm` |
| `scale` | `max_weight_kg`, `division_g`, `label_printing` (true/false), `connectivity` |
| `pos` | `type` (`pos_terminal` / `computer` / `laptop` / `monitor` / `other`), `cpu`, `ram_gb`, `storage_gb`, `screen_inch`, `os` |
| `rfid` | `kind` (`tag` / `reader` / `printer` / `antenna`), `frequency` (`uhf` / `hf` / `lf`), `read_range_m` |
| `software` | `works_with` (массив, например `["1c", "moysklad"]`), `license` (`perpetual` / `subscription`) |
| `service` | `unit` (`visit` / `hour` / `device`) |

Числа передавайте числом (`104`, а не `"104 мм"`), логические значения как `true` / `false`.

## 5. Проверки на стороне сайта

- Товар с ошибкой (нет `sku`, неизвестная `category`, цена не целое число…) пропускается и попадает в `rejected`, остальные товары принимаются.
- Выгрузка отклоняется **целиком** (код `422`, ничего не меняется), если:
  - список `products` пуст, в нём нет ни одного корректного товара или больше 20 000 товаров;
  - корректных товаров меньше половины от каталога на сайте (защита от пустой или обрезанной выгрузки; проверка действует, когда в каталоге 10 товаров и больше);
  - `sku` повторяется (без учёта регистра и пробелов по краям);
  - `clients` есть, но это не список, или в нём больше 10 000 записей;
  - JSON не читается.
  Администраторы сайта получают уведомление в Telegram.
- Товары из прошлой выгрузки, которых нет в новой, скрываются от AI.
- Если выгрузок не было дольше настроенного срока (по умолчанию 24 часа), AI перестаёт называть цены и наличие и отвечает «менеджер уточнит».
- Максимальный размер тела 20 МБ; около 5 000 товаров помещаются с запасом.

## 6. Приёмка

1. Откройте адрес сервиса в браузере под пользователем `bdb_site`: должен открыться JSON.
2. Проверьте JSON на 3–5 известных товарах: цены всех трёх видов, остаток, параметры.
3. Передайте нам адрес, логин и пароль (пароль отдельным сообщением). Мы включим режим Pull и нажмём «Загрузить сейчас». В админке сайта будет видно, сколько товаров принято и какие отклонены.
4. Для режима Push мы выдадим токен. После первой отправки проверьте ответ `accepted` / `rejected`.
